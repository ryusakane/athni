# AthNi の仕組み（全体説明）

サービスの目的、サイトの構成、データ、アカウントと本人確認、運営作業をまとめた説明書です。
**機能や運用ルールを変えるPRでは、同じPRでこのファイルも更新します**（`CLAUDE.md` のルール）。
最終更新: 2026-10-09

## 1. サービス

- 高校生アスリートがアメリカの大学へアスレチック・リクルートで進学するのを支援する（最初はゴルフ）。
- 対象は世界中の高校生（日本から開始）。サイトの文言では「日本の」に限定しない。
- 読み手: 選手、保護者、高校の指導者、アメリカの大学コーチ。
- 運営: Athni株式会社 / Athni Inc.（ロゴ表記 AthNi）。ドメイン athtouni.com。

## 2. 技術構成とコスト

| 役割 | 使っているもの | 費用 |
| --- | --- | --- |
| サイト | Next.js（App Router）+ TypeScript + Tailwind。静的ファイルとして書き出し（`output: "export"`） | 0円 |
| 公開 | Cloudflare Workers（Worker 名 `athni`、静的アセット配信）。main にマージすると自動で本番に反映。PRごとにプレビューURLが出る | 無料枠 |
| DB・ログイン | Supabase（無料プラン、project `ynapxeymwrhtijbnijaz`） | 無料枠 |
| CI | GitHub Actions（`npm run lint` と `npm run build`） | 無料 |
| メール | Google Workspace（athtouni.com） | 契約中 |

- 方針: 費用はできるだけかけない。有料サービスは必要になるまで使わない。
- Cloudflare 無料枠は 1回のデプロイで 2万ファイルまで。ページを増やすときはファイル数に注意する。
- ログイン機能はブラウザから Supabase に直接つながる。だれが何を見られるかは、DB の行レベルセキュリティ（RLS）ですべて決めている。

## 3. ページ構成

すべて `/en/...`（英語）と `/ja/...`（日本語）の2言語。`/` はブラウザの言語で振り分け。

| ページ | パス | 内容 |
| --- | --- | --- |
| トップ | `/[lang]/` | サービスの説明と主な導線 |
| 選手一覧・詳細 | `/[lang]/players/`, `/players/[id]/` | 公開されている大会結果から作った高校生ゴルファーの成績 |
| 大会一覧・詳細 | `/[lang]/tournaments/`, `/tournaments/[id]/` | 大会、順位、ラウンドごとのスコア、コース情報、天候 |
| 大学一覧・詳細 | `/[lang]/colleges/`, `/colleges/[slug]/` | NCAA D1 のゴルフ部（コーチ、ロースター、OB/OGプロ、ランキングなど）。未収集の項目は「未収集」とだけ表示 |
| 会社概要・問い合わせ | `/[lang]/about/`, `/contact/` | |
| 登録・ログイン・マイページ | `/[lang]/signup/`, `/login/`, `/account/` | アカウント機能（5章） |

コードの場所: ページ `src/app/[lang]/`、部品 `src/components/`、翻訳 `src/i18n/`（アカウント関係は `src/i18n/account.ts`）。

## 4. データ

### 高校生ゴルフの成績

- 出典: 各地の連盟などが公開している大会結果。英語表記、スコア、大会、順位、コースレート・スロープ、天候をそろえる。
- 元データと作り方: `data/`（説明は `data/README.md`、出典の一覧は `data/SOURCES.md`）。
- 再利用の許可がない出典は載せない（関東高ゴ連は同意を得るまで非公開、JJGA・JGTO なども保留）。
- 選手の英語名は推定を含む。北海道は未収集。
- 同じ選手の名寄せ: 名前が同じで、学校・県・卒業年度のうち2つ以上が一致すれば同一人物として1人にまとめる（学校名は略称・表記ゆれも同じ学校とみなす。同じ大会に両方出ている2人はまとめない）。学校も卒業年度もわからない記録（日本ジュニア・国スポなど）は、食い違いのない同名の選手が1人だけなら仮にまとめる。
- まとめなかった同姓同名と、仮にまとめた組は `data/player_name_review.csv` に出し、人が判断する。判断は `data/reference/player_merge_decisions.csv` に `same` / `different` で書くと次の生成から反映される。
- サイトと Supabase に載せる大会は `data/supabase/published_tournaments.txt` に絞っている（静的ファイル数を Cloudflare 無料枠に収めるため）。
- サイトはビルド時にデータを読む。Supabase の接続情報があれば Supabase から、なければ `src/data/seed.json` から。

### 大学

- NCAA D1 の全校（338校・601チーム）。元データとルールは `data/colleges/`（`README.md`）。
- 未収集の理由は社内用の `data/colleges/ISSUES.md` だけに書き、サイトには出さない。
- ランキングのシーズンは「2026–27」のように表示する（7月始まり）。

### DB のテーブル定義

`supabase/migrations/` に番号順に並んでいる（0001 成績、0003 大学、0004 アカウント、0007_identity_checks 本人確認、0008 生徒プロフィール項目、0009 ロードマップの進捗、0010 生徒の書類、0011 住所・高校と成績の本人確認 など）。
本番 DB への適用は Supabase に対して行い、同じ内容をこのフォルダにも残す。

## 5. アカウントと立場

登録時に立場を選ぶ。1つのサイトで全員が使う。

| 立場 | できること |
| --- | --- |
| 生徒（選手） | プロフィール、学業・英語・テストのスコア、ゴルフの情報、志望校リストを入力する。大学コーチに公開するかどうかを自分で選ぶ |
| 保護者 | 生徒の招待コードで連携し、プロフィールの閲覧と入力の手伝いができる（任意） |
| 大学コーチ | 選手を探して保存する。認証済みのコーチだけが、公開している生徒のプロフィールを見られる |
| 高校の指導者 | テーブルだけ用意してあり、まだ登録画面には出していない |

- 保護者の同意は不要（SNSと同じ考え方。生徒が自分で公開範囲を決める）。
- 大会成績は生徒が直接追加できない。「これは自分です」の申請と、載っていない大会の申請だけを受け付け、運営が確認して反映する。

### 住所・高校と、ログイン後の「この成績はあなたですか？」

- 生徒は登録時に、国・都道府県（日本以外は州など）・住所・高校を入れる。日本の都道府県は一覧から選び、「東京都」のように日本語の名前で保存する（大会データと比べるため）。後からマイページのプロフィールで直せる。
- 番地までの住所は別のテーブル `student_addresses` に置き、本人と連携した保護者だけが見られる。大学コーチに見えるのは国と都道府県（州）まで。
- ログインすると、マイページの最初に、登録した氏名と同じ名前で、都道府県か高校も一致する大会成績の選手を表示する（DB 関数 `player_matches`）。名前は漢字・フリガナ・英語のどれかが一致すればよい（空白、全角半角、カタカナとひらがな、﨑/崎などの字体の違いは無視）。高校名は「県立」「高等学校／高校」などを除いて比べる。
- 生徒は候補ごとに「自分です」か「自分ではない」を選ぶ。「自分です」は「これは自分です」と同じ申請（`player_claims`、`source = 'profile_match'`）になり、運営が承認してから成績がプロフィールに付く。「自分ではない」は `student_player_dismissals` に残り、もう表示しない。
- 都道府県か高校がまだ入っていない生徒には、先にその入力を求める。「あとで」を押すと、そのブラウザのタブを閉じるまで表示しない（次に開いたときにまた出る）。
- すでに運営が別のアカウントに承認した成績は候補に出さない。

### 生徒の書類

- 通知表・成績証明書、卒業証明書、英訳、テストのスコアレポート、オファーの書面、I-20、ビザを、マイページの「書類」からアップロードできる。テストのスコアごとにスコアレポートも添付できる。
- ファイルは Supabase Storage の非公開バケット `student-documents`（生徒IDのフォルダ）に置き、一覧は `student_documents`。PDF か画像、10MB まで。
- 開けるのは生徒本人と連携した保護者だけ（開くときは60秒だけ有効なリンクを発行）。大学コーチや運営の画面には出さない。
- 無料枠のストレージは 1GB。利用者が増えたら容量を確認する。

### 入学までのロードマップ（生徒のマイページの一番上）

- 高校から大学入学までにやることを、4段階・18ステップで順番に表示する（準備 → コーチに知ってもらう → 訪問とオファー → 入学手続きとビザ）。
- 「いまここ」に最初の未完了ステップを大きく出し、やること・目安の時期・出典を表示。下に「次にやること」。全ステップは開いて見られる。
- 目安の時期は、生徒が入れた「入学したい年」の8月から逆算する。過ぎていると色が変わる。
- 完了の付け方は2つ。プロフィールの入力から自動で判定するもの（例: NCAA 登録状況、英語テストのスコア、動画リンク、志望校のステータス）と、生徒が「完了にする」を押すもの。押したものは `student_roadmap_steps` に保存。
- 各ステップに「登録済みの内容」（例: 英語ステップなら入力済みのスコア）と、入力する欄へのリンクを出す。書類が関係するステップ（成績、英語、出願、I-20、ビザなど）では、その場で書類をアップロードできる。
- 見られるのは生徒本人と連携した保護者だけ。大学コーチには見えない。
- ステップの文章と出典は `src/i18n/roadmap.ts`（2026-10-08 時点で確認）。NCAA の規則、英語テストの基準、ビザの費用などが変わったら、ここを直す。

## 6. 本人確認と信頼の仕組み

目的は、未成年の情報を見る側（大学コーチ）を確実に確かめることと、成績が本人のものだと示すこと。身分証の提出は求めない（国ごとに書類が違い、保管のリスクもあるため）。

| 立場 | 確認のしかた |
| --- | --- |
| 大学コーチ | 大学のコーチ紹介ページから集めた名簿（`college_coaches`）に載っているメールアドレスで登録し、メールを確認すると自動で認証される。.edu のアドレスだけでは認証しない（大学生も持っているため）。それ以外は運営が確認するまで「確認待ち」 |
| コーチの代理（アシスタントなど） | アカウントは共有しない。認証済みのコーチが、同じ大学ドメインのメールアドレスで招待する（フリーメールは不可）。招待を取り消すか、招待したコーチが認証から外れると見られなくなる |
| 外部の仲介エージェント | 当面は登録も招待も不可 |
| 生徒 | 成績の紐付けは運営が承認する。申請するときに証拠のリンク（名前が載っている結果ページなど）を付けられる。コーチ画面では、承認済みの成績に「AthNi確認済み」、GPA などには「本人の入力」と表示する |
| 保護者 | 書類は求めない。生徒が招待コードを渡したことを本人の承認とみなす。生徒はいつでも連携を解除でき、コードを作り直せる |

有料の本人確認サービスは、有料プランを始めるまで使わない。

## 7. 運営の作業（現状は Supabase の画面で行う）

- **コーチを手動で認証する:** `coach_profiles` で `verification_status = 'verified'`、`verification_method = 'staff_review'` にする。認証できない場合は `rejected`。
- **「これは自分です」の申請:** `player_claims` の `status` を `approved` か `rejected` にする（`evidence_url` を確認）。`source = 'profile_match'` はログイン後の候補一覧から選ばれたもの（名前と、都道府県か高校が一致している）。
- **載っていない大会の申請:** `result_requests` の `source_url` を確認し、大会データに追加してから `status = 'added'` にする。
- 管理用の画面はまだない。
